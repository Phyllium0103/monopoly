# 地圖效能與載入流程

本輪只修改本機遊戲，沒有 push 或部署。原始精修 GLB、原美術與既有開發草稿均保留。

## 遊戲前的讀條

`index.html` 先顯示載入頁，`Game.prepare` 依實際完成的資源更新進度。地形與道路、20 種建築的 3 級 LOD、物品包、地圖主公立繪、53 張縮小的人物動畫貼圖、骰子 GLB 與物理 Worker，以及首次 GPU 準備均完成後，才進入選單或開始對局。失敗時保留畫面並提供重新載入。

所有 LOD 預先備妥，避免後續城池升級與縮放再下載。這個選擇會增加初次等待：60 個 GLB 合計約 80.6 MB；不能把它宣稱為下載量比原本 20 個 GLB 更少。後續畫面使用較少三角面，依單棟可見性及縮放選擇 LOD，不再解碼後逐頂點合併。

## 地圖用模型

實際資產由 `public/art/map-runtime/manifest.json` 與 `src/data/mapRuntimeModels.ts` 指定。檔名包含內容雜湊。原版 `public/art/map-selected` 仍保存，遊戲不會同時載入兩套。

離線處理會合併相容材質、產生三種精度、壓縮 512px WebP 材質圖、移除不必要的實體透射等效果，保留薄紙／植栽必要的雙面與城池換色標記。礦石、玻璃改以輕量透明材質呈現。

Meshopt 的頂點可能是正規化整數。`MapModelPool` **必須保留 GLB 節點矩陣，將其乘入每個實例的矩陣**。不可直接把世界座標寫回整數頂點，否則會溢位而壓壞模型。

更新原模型後，先更新原模型清單，再重建遊戲用版本：

```powershell
npm ci --prefix scripts/map-runtime-tools
node scripts/map-runtime-tools/build.mjs
```

工具依賴與鎖定檔隔離在該資料夾，不加入遊戲的執行依賴，也不在每次一般 build 時重新減面。重建後需檢查縮放、門窗與階梯等輪廓、城池換色，以及清單所指的實際檔案。請勿將歷史孤立產物加入新發布清單。

## 背景計算與繪圖

- 骰子 Rapier 模擬與 P2P 房主的種子重播使用各自 Worker；物理步長、骰面與遊戲規則保留。
- 房主存檔 JSON 序列化放入 Worker，拒絕已過期回應；離頁時仍同步保存，維持原存檔格式。
- Worker 不支援或失敗時可退回原邏輯；骰子的主執行緒退路分段讓出執行時間。失敗的 Worker 不反覆建立，逾時不會留下未完成的 Promise。
- 人物只在動作或位置改變時繪圖。地圖靜置上限 30 FPS，互動與移動仍依瀏覽器更新；戰鬥／賭場覆蓋時降低底圖繪製頻率。繪圖節流不停止遊戲更新。
- 高 DPI 地圖有 250 萬像素預算，透明人物／骰子畫布各 160 萬；DOM 文字維持原生解析度。

## 限定驗證

本輪沒有執行全套遊戲或多人壓力測試。只檢查相關回歸與正式建置：

```powershell
node tests/map-runtime.cjs
node tests/performance-workers.cjs
node tests/lord-actor-hud.cjs
npm run build
```

檢查包含量化矩陣、單棟剔除／LOD、換色與 instance 重用、讀條、Worker 失敗／逾時、一顆真實物理骰的精確傳輸、一次種子規則重播及存檔格式、原人物回合姿勢。另做少量真實瀏覽器讀條、縮放及一次擲骰移動核對。


## 單份壓縮模型更新

依使用者要求，每種建築只載入最高精度的既有壓縮版（LOD0），20份合計50,413,844 bytes；不再預載或隨縮放切換另外兩種精度。保留單棟剔除、實例共用與節點矩陣。最多三個載入作業並行。60份歷史GLB均已核對Meshopt幾何與WebP內嵌貼圖，沒有未壓縮原檔混入目前運行路徑。原模型與未選LOD保留在資產資料夾，不會因保留而被遊戲載入。
